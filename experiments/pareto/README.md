# Исследование качества и задержки реконструкции

Это отдельный протокол v2 для новых опытов. Его числа нельзя выдавать за
воспроизведение старых графиков курсовой. Исходное состояние проекта:
`7f85f4b23daf98da517bbac49b48899035b383fa`.

В Colab откройте `notebooks/Tracking_Pareto_Colab.ipynb`. Он загружает конкретный
коммит и импортирует модули проекта. Начните с `smoke`, затем используйте `screen`.
Профиль `paper` предназначен для окончательной серии и заметно дороже.

Новые события создаются через существующие `ParticleGenerator`, конфигурацию
`example_generator_config` и `NaiveDetector`. Аналитический распространитель
`generator.analytic` применим только к прямым по z частицам и полю вдоль z.
Общий пошаговый распространитель остаётся доступен отдельно. В новой версии
исправлены знак и величина поворота импульса, область шума, продолжение случайной
последовательности детектора между событиями, нумерация хитов и передача seed.
Исторические результаты относятся к прежнему коду и требуют самостоятельной проверки.

Новый протокол также меняет оценку и декодирование:

- Эталонные треки задаются идентификатором частицы и минимумом трёх исходных хитов;
  после фильтрации эталон не пересчитывается.
- Допустимые пары имеют purity и completeness не меньше 0,8. Сопоставление
  взаимно однозначно, число пар максимально; дубликаты снижают precision.
- F1 вычисляется micro по событиям, затем усредняется по seed обучения.
- Greedy и beam используют одинаковые ограничения на общие хиты и прямой обход;
  приоритет имеет длина пути, затем средняя log-вероятность. Это новые декодеры.
- Каждый слой EdgeConv имеет собственный MLP. Пороги применяются после sigmoid.
- Время включает построение графа из CPU-массивов, переносы, фильтр и обрезку,
  классификатор рёбер и декодер до CPU-списка кандидатов. Симуляция и оценка
  качества исключены. Выполняются прогрев и синхронизация CUDA.
- Граф строится только между соседними числовыми слоями. В этом выпуске k=1
  при обучении и оценке. Нормализация координат выполняется по событию.

Основной перебор проводится на validation. Для пяти бюджетов времени выбирается
до пяти конфигураций, список фиксируется до test. Тест не используется для
поиска новых порогов. Дополнительная проверка устойчивости использует те же
веса и конфигурации при изменении числа частиц или интенсивности фона.

Фильтр и модель рёбер обучаются на исходных графах. В сравнении «фильтр включён /
выключен» веса модели рёбер постоянны. Переобучение на очищенных графах — отдельный
возможный эксперимент. Локальная F1 рёбер после фильтрации условна по сохранённому
подграфу; основной критерий — F1 треков относительно полного исходного эталона.

Сохраняются все CSV, конфигурации, исходные повторы времени, manifest со средой,
разбиение данных, веса и графики. Не объединяйте времена разных GPU в одну
границу Парето. Bootstrap-интервалы качества являются описательными; один seed
проверяет выполнение, три seed дают лишь ограниченную оценку вариативности.

Локальные проверки без PyTorch:

```bash
python -m pip install -r requirements.txt scipy
python -m unittest discover -s tests -v
python -m tests.check_pareto_core
```

Для обучения нужен установленный PyTorch, соответствующий оборудованию, затем
`pip install -r experiments/pareto/requirements.txt`. Colab использует встроенный
PyTorch. Проверки генератора и численного ядра выполнены; обучение и полный
GPU-конвейер требуют первого запуска `smoke` в Colab.
